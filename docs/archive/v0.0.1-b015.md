# v0.0.1-b015

Version : v0.0.1-b015
Date    : 2026-06-04
Status  : Alpha

## Changes

S : `F-TY-2` *fixed (partial)* — Result and Option payloads widened from a single `int64_t` to a 16-byte `urus_payload_t` union covering `int64 / uint64 / double / void* / urus_str / uint64[2]`.  Before this build, every `Ok(str)`, `Some(str)`, `Ok(double)`, and `Some(double)` silently truncated half the value (the str length, or the float's bit pattern routed through `(int64_t)(intptr_t)v`).  v0.0.1-b015 picks the correct arm via a `_Generic` constructor (`URUS_PAYLOAD_OF`) so the calling code does not need a manual cast.  Payloads larger than 16 bytes still require boxing in v0.0.1 — that limit is enforced statically by `_Static_assert(sizeof(urus_payload_t) == 16, …)` so the layout never silently drifts.
A : `urus_payload_t` union — 16-byte payload storage with named arms for every primitive plus `urus_str` and a `uint64_t raw[2]` escape hatch.
A : `URUS_PAYLOAD_OF(v)` `_Generic` dispatcher — fills the correct arm based on the static type of `v`.  Pre-C11 fallback keeps emitting the `int64` arm so legacy toolchains do not break.
A : `urus_payload_str(x)` / `urus_payload_ptr(x)` / `urus_payload_f(x)` / `urus_payload_u(x)` / `urus_payload_as(x, T)` — typed accessors so generated code can pull the right arm without aliasing `int64`.
A : `tests/run/14_result_str_payload.urus` — Result<str, str> round-trips both arms without dropping the length.
A : `tests/run/15_option_float_payload.urus` — Option<f64> survives the round-trip with its bit pattern intact.
U : `urus_ok` / `urus_err` / `urus_some` constructors now compose with `URUS_PAYLOAD_OF` instead of casting through `(int64_t)(intptr_t)`.
U : `urus_payload(x)` keeps the `.i` (int64) arm semantics for back-compat — every existing caller (the `?` operator's `urus_payload(_t)`, match arms binding to an `int` payload) keeps working.  New code with non-int payload should use `urus_payload_str` / `urus_payload_f` / `urus_payload_as`.
N : This closes the **last** outstanding stop-ship finding from the 2026-06-03 audit — **all 10 of 10 are now resolved across b011 → b015**.  Honest scorecard: compile-time safety on the four `F-COMP-*` axes is real; runtime payload corruption on the two `F-TY-*` axes is gone for ≤16-byte values, still requires manual boxing past that.  Memory-safety from `F-MEM-*` is closed end-to-end.
N : *Why "partial" on F-TY-2:* a future v0.0.2 monomorphisation pass will pick a per-instantiation payload size, which makes the 16-byte cap obsolete and lets `Result<BigStruct, str>` work without manual boxing.  Tracking under Tier-1 issue *"F-TY-2 full close: monomorphise Result/Option"*.
