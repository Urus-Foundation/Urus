# v0.0.1-b026

Version : v0.0.1-b026
Date    : 2026-06-04
Status  : Alpha

## Changes

C : **`diag_fatal` no longer hard-kills embedders.**  `DiagCtx` gained a `jmp_buf recover` + `can_recover` flag; `diag_set_recovery(d)` arms it.  With an armed recovery point, `diag_fatal` longjmps back to the embedder after printing; without one (bare CLI) it keeps the `exit(2)` contract.  `urus_compile_buffer` arms the point around the whole pipeline, so a fatal anywhere inside lex/parse/sema/codegen returns control with `rc = 1` and truthful error counts — no process death.
C : `URUS_NORETURN` dropped from `diag_fatal`'s declaration — with the longjmp path, the attribute would let optimizers elide embedder cleanup that *does* run.  Behaviour is unchanged for callers: the function still never returns normally.
S : Direct consequence for the b023 fuzzer: a `diag_fatal` during fuzzing no longer terminates the fuzz process silently (which looked like a pass).  Fatal paths now return to `LLVMFuzzerTestOneInput` like any rejected input, keeping the campaign running and the coverage honest.
N : *Known limitation:* `arena.c` and `strbuf.c` still `exit(1)` on true OOM.  Converting those requires threading a `DiagCtx` through both utility layers — scheduled for v0.0.2 alongside the allocator-failure-injection test rig.  Under fuzzing, `-rss_limit_mb` + ASan intercept allocator failure before these paths fire.
N : The CLI (`main.c`) intentionally does **not** arm recovery — `urusc` should die with exit 2 on fatal, same as every other compiler.
