## Changes

A : **`--max-input-bytes N[K|M|G]`** CLI flag — runtime override for the input size cap (Tier-0 item #11 follow-up; the audit closed the cap in b011 but left the override flag TODO).  Default stays 64 MiB; the override is bounded above at a hard 1 GiB ceiling (`URUS_INPUT_CAP_CEILING`) so the flag cannot disable the cap outright.  `0`, malformed, or above-ceiling values are rejected at argv-parse time.
A : `parse_size_arg` — strict size parser (`N`, `NK`, `NM`, `NG`; errno-checked `strtoull`; no trailing garbage).
U : **Test harness rewritten** (`scripts/run-tests.ps1` + `scripts/run-tests.sh`):
    - Marker support in the first 30 lines of each test: `// harness: skip` (documentation marker, not executed) and `// harness: args <flags>` (per-file extra urusc flags).
    - Harness self-tests: compiles a known-good file with `--max-input-bytes 16` and requires refusal; passes `--max-input-bytes 0` and requires the invalid-value error.
    - Both runners now report `passed / failed / skipped` and exit non-zero on any failure (CI-ready).
U : `tests/fail/SEC-03_input_too_large.urus` tagged `harness: skip` — it is a documentation marker that compiles cleanly, which would have false-failed the fail-suite.  The actual cap behaviour is now covered by the harness self-test.
U : `read_file` diagnostic now mentions the flag: `…the limit is N bytes (raise with --max-input-bytes, ceiling 1G)`.
I : `compiler/src/main.c` gained `<errno.h>`; the cap comparison reads `g_max_input_bytes` instead of the compile-time constant.
N : The PowerShell runner is the canonical Windows path (no `gcc` needed — `--emit-c` only).  The POSIX runner mirrors it byte-for-byte in behaviour for the CI matrix landing in b022.
