# v0.0.1-b030 — 2026-06-06

> **Status:** Alpha
> **Theme:** First end-to-end verified build — every `tests/run` program
> and every example now compiles to C **and runs** with the correct
> output. The e2e sweep surfaced 13 latent codegen/parser/runtime bugs
> that `--emit-c`-only verification had been masking; all are fixed.

This is the first build produced on a machine with a working host C
toolchain (zig cc). Until now the test harness only proved that `urusc
--emit-c` exits cleanly; b030 proves the emitted C compiles and the
binaries behave.

## Changes

- `S` `compiler/src/main.c` — codegen-stage diagnostics are now checked
  **before** the output file is written. Pre-b030, an f-string
  placeholder rejection (F-MEM-1 family) printed its error but still
  wrote the poisoned artifact and returned exit 0 — silently undoing
  the SEC-08/09/10 gate for build-system callers. (`urus_compile_buffer`
  already checked; only the CLI path was open.)
- `F` `stdlib/runtime/urus_rt.h` — `URUS_PAYLOAD_OF` and `URUS_FMT_ANY`
  rewritten from value-selecting `_Generic` to **function-selecting**
  `_Generic`. The old form type-checked every association even when not
  selected, so any expression of type `urus_str` failed to compile
  (`(void *)(v)` on a struct). This made every Result/Option
  construction in emitted C a compile error on real toolchains.
- `F` `compiler/src/codegen_c.c` — block tails in `void` functions no
  longer emit `return expr;` (a C constraint violation), and
  control-flow tails (`return`/`break`/`continue`) no longer emit
  `return return …`.
- `F` `compiler/src/codegen_c.c` — `match` is now **value-producing**
  (chained conditional expressions over statement-expressions instead
  of an `if`/`else` statement chain), so `let x = match … { … }` and
  tail-position matches compile.
- `F` `compiler/src/codegen_c.c` — F-TY-2 **read side**: payload
  *extraction* now picks the union arm matching the static payload type
  (`urus_payload_str` / `_f` / `_u`), driven by a minimal per-function
  local-type table (annotation → initializer → fn return type;
  `read_line()` mapped to `Option<str>`). Pre-b030, `Ok("hello")`
  round-tripped through the `int64` arm and printed the pointer value.
  Construction-side widening shipped in b015; extraction had never been
  exercised end-to-end.
- `F` `compiler/src/codegen_c.c` — `self` is rewritten to the C
  parameter `self_` (with `(*self_)` deref for `&self`) in identifier
  *and* f-string-placeholder positions; method bodies using
  `{self.field}` now compile.
- `F` `compiler/src/codegen_c.c` — `Type.method(args)` with a type-name
  receiver is emitted as a **static call** (no `&self` argument);
  `Aurochs.new(…)` no longer produces `Aurochs__new(&(Aurochs), …)`.
- `F` `compiler/src/codegen_c.c` — user-enum support in expressions:
  `Enum::Variant` in value position constructs the tag-holding struct
  via compound literal, and `match` arms over user enums compare
  `_scrut.tag` instead of emitting `1 /*unknown variant*/` (which made
  every arm truthy and took the first arm unconditionally).
- `F` `compiler/src/parser.c` — trailing semicolons are now **optional**
  after `let`, `use`, `const`, and `type` declarations, matching the
  documented "semicolons are optional" rule (`expect` → `match`).
  Pre-b030, every semicolon-free test program failed to parse.
- `F` `compiler/src/parser.c` — `match` arms with block-like bodies
  (`{}`, `if`, `match`, loops) no longer require a trailing comma
  (Rust-style separator rules); fixes `examples/grades.urus`.
- `F` `compiler/src/parser.c` — depth-cap filler used stale `TY_NAME`
  enumerator (compile error since the AST rename to `TY_NAMED`).
- `F` `compiler/src/lexer.c` / `include/lexer.h` /
  `include/arena.h` — `Arena` is now a named struct so the
  `struct Arena *` forward references in headers and the `Arena *`
  definitions in `.c` files are the same type (was a conflicting-types
  error under zig cc/clang).
- `F` `compiler/src/codegen_c.c` — missing `#include <stdarg.h>`
  (`va_start`/`va_end` were implicit declarations, hard error under
  C99+ rules).
- `U` `tests/run/06_fstring.urus` — `{4}` placeholder replaced with a
  bound `{four}`; literal expressions in placeholders are rejected by
  design since the b014 F-MEM-1 validator landed.
- `U` `scripts/run-tests.ps1` — `$ErrorActionPreference` `Stop` →
  `Continue`: urusc reports status on stderr, and Windows PowerShell
  5.1 wraps native stderr in ErrorRecords under `2>&1`, which threw on
  the very first PASS. Failure detection rides `$LASTEXITCODE`, as
  before.
- `T` Full e2e matrix now green: 43 harness tests passed (23 run + 18
  fail + 2 self-tests, 1 skip marker), 23/23 run-tests and 6/6 examples
  compiled with `zig cc -std=gnu11` and executed with expected output.
- `N` Known limitation carried forward: the codegen local-type table is
  best-effort (no inference through arbitrary expressions); unknown
  payload types still degrade to the `int64` arm — wrong value, never
  UB. Full typed sema lands in v0.0.3.
