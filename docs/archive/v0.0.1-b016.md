# v0.0.1-b016

Version : v0.0.1-b016
Date    : 2026-06-04
Status  : Alpha

## Changes

S : *Tier-1 hardening — integer literal overflow now detected.*  Pre-b016 the lexer trusted `strtoull` to surface overflow but did not actually check `errno`, so a literal like `999999999999999999999` lexed as `2^64 - 1` (the saturated return) and the program silently compiled with a corrupted constant.  `lex_number` now zeroes `errno` before each call, refuses values above `UINT64_MAX`, and emits `integer literal does not fit in u64 (max …)` with the literal's source location.
S : *Tier-1 hardening — float literal overflow detected.*  `strtod` `ERANGE` is now surfaced as `floating-point literal out of range for f64` instead of silently producing `±HUGE_VAL`.
S : *Tier-1 hardening — source input must be valid UTF-8.*  `read_file` now scans the buffer through `urus__utf8_first_bad_offset` and rejects embedded NULs, overlong encodings, lone surrogates, codepoints above U+10FFFF, and stray continuation bytes.  The diagnostic prints the 1-based byte offset of the first malformed byte.  Closes two latent bugs at once: (a) a single embedded `\0` no longer truncates the lexer's view of the file mid-stream, (b) WTF-8 / Modified-UTF-8 sequences emitted by some Windows editors are now hard rejects rather than silently misinterpreted character literals.
S : *Defensive — number literal type-suffix stripped before parse.*  Pre-b016 a literal like `10u32` was fed through `strtoull` as-is, which returned `10` (stopping at `u`) — correct by accident.  `lex_number` now explicitly drops the trailing alpha suffix before parsing, so an empty-base literal (`0x` with no digits) raises `integer literal has no digits after base prefix` instead of falling through to a no-op parse.
A : `urus__utf8_first_bad_offset(p, n)` — UTF-8 well-formedness scanner returning the 1-based offset of the first malformed byte, or 0 if the whole buffer is valid.
A : `tests/fail/SEC-11_int_overflow.urus` — `999999999999999999999` rejected.
A : `tests/fail/SEC-12_hex_overflow.urus` — `0x1_0000_0000_0000_0000` rejected.
U : `compiler/src/lexer.c` — adds `<errno.h>`, `<limits.h>`, `<stdint.h>`, `<diag.h>`; switches the integer / float parse block over to the errno-checked form described above.
U : `compiler/src/main.c` — calls `urus__utf8_first_bad_offset` immediately after the `fread` + zero-tail step.  Validation failure prints a diagnostic and frees the buffer; the compiler exits non-zero before the lexer ever sees the bytes.
N : Tier-0 stop-ship list stays at 10-of-10 closed (b011-b015).  b016 is the first build attacking the Tier-1 list (items 16-40 in `docs/security/SECURITY-AUDIT.md`).  Three Tier-1 items landed here: numeric-literal overflow, UTF-8 validation, and the suffix-stripping defensive parse.
