## Changes

A : **`urus.io.read_line`** — first interactive-input primitive.  Returns `Option<str>`: `Some(line)` without the trailing newline (CRLF-tolerant — one trailing `\r` is stripped for Windows pipes), `None` on immediate EOF or allocation failure.  Line length capped at `URUS_READLINE_MAX_BYTES = 16 MiB` (same budget as the string-literal lex cap); past the cap the line is truncated and the remainder drained so the next call starts on a fresh line.
A : `URUS_READLINE_MAX_BYTES` runtime constant (16 MiB).
A : Codegen maps the surface name `read_line()` to the runtime symbol `urus_read_line()` (same pattern as `println` → `urus_println`).
A : Sema prelude registers the b017 string helpers (`urus_str_len`, `urus_str_is_empty`, `urus_str_eq`, `urus_str_cmp`, `urus_str_starts_with`, `urus_str_ends_with`, `urus_str_contains`) and the new `read_line` / `urus_read_line` pair, so programs can call them without tripping the undefined-name check.
A : `tests/run/18_read_line.urus` — Some/None match over a piped stdin line.
N : Ownership: the `str` returned by `read_line` owns a heap allocation that v0.0.1 deliberately leaks (no ownership tracking yet) — same policy as `urus_fmt_to_str_n`.  The arena story in v0.0.2 will reclaim both.
N : `urus_read_line` grows its buffer geometrically from 256 B and respects the cap during growth, so a hostile "infinite line" on stdin costs at most 16 MiB + drain time, not an OOM.
