# v0.0.1-b025

Version : v0.0.1-b025
Date    : 2026-06-04
Status  : Alpha

## Changes

S : *Diagnostic output amplification fixed.*  Snippet lines are now windowed to `URUS_DIAG_MAX_SNIPPET = 120` columns centred on the caret, with `…` markers on clipped sides.  Pre-b025 a 16 MiB single-line source printed the entire line on every diagnostic — one malformed file could turn into gigabytes of stderr (a DoS on CI log storage and a foot-gun for editors capturing compiler output).  Caret spans are clamped to the same window.
S : *Error-flood cap.*  Diagnostics stop printing after `URUS_DIAG_MAX_ERRORS = 64` errors, with a one-time `too many errors (64) — further diagnostics suppressed` notice.  Counting continues so `diag_has_errors` / exit codes stay truthful; warnings and notes also stop printing under an error avalanche (they would only add noise).
C : All five emit paths (`diag_emit` / `diag_note` / `diag_warn` / `diag_error` / `diag_fatal`) now route through one `diag__vemit` helper — pre-b025 `diag_note` lacked the snippet and colors entirely, and `diag_fatal` lacked colors.  Output format is now uniform: colored level prefix, message, `--> file:line:col`, windowed snippet with caret.
N : `diag_fatal` still calls `exit(2)` (contract: `URUS_NORETURN`).  Under the b023 fuzzer an `exit()` terminates the fuzz process without a crash report; the only fatal site today is `lex_string`'s OOM path, which ASan would catch first.  Converting fatal to longjmp-unwind is v0.0.2 work (needed for LSP hosting anyway).
