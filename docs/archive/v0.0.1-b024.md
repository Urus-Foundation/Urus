## Changes

L : **`while let PAT = EXPR { BODY }`** — first syntax sugar in the language.  Desugars *in the parser* to `loop { match EXPR { PAT => BODY, _ => break } }`, so no new AST node, and sema's existing machinery (F-COMP-3 exhaustiveness, binding rules, immutability of match bindings) applies to the desugared form for free.
F : **For-range codegen hardening** — two latent crash/miscompile paths in `EX_FOR`:
    - Non-range iterator (`for x in some_call()`) previously emitted the bare C comment `/* unsupported for-loop iterator */` mid-expression — the *host* compiler then failed on broken C, or worse, silently compiled the surrounding statement-expression with no loop at all.  Now a URUS-level diagnostic: `v0.0.1 'for' only supports range iterators`.
    - Half-open range (`for i in 0..`) fed `range.end == NULL` straight into `cg_expr`, producing `/*null*/0` C output that compiled into an always-false loop bound.  Now diagnosed: `'for' needs both range bounds`.
    Both error paths emit `((void)0)` as the expression placeholder so the emitted C stays parseable for any later diagnostics in the same TU.
A : `tests/run/20_while_let.urus` — Some/Some/None driver loop, expects two iterations.
A : `tests/run/21_for_range.urus` — exclusive (`0..5`) + inclusive (`1..=3`) accumulate to 16.
A : `tests/fail/SEC-17_for_no_bounds.urus` — `for i in 0..` rejected cleanly.
N : `while let` lives entirely in `parser.c:TOK_KW_WHILE`; the lookahead is a single `check(p, TOK_KW_LET)` so plain `while cond {}` parsing is untouched.
