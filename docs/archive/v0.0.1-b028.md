Status  : Alpha

## Changes

F : **`defer` now fires on every exit edge** — the sharpest documented footgun left in the language ("mixing `defer` and early returns is unsafe today") is gone.  Three exit paths covered:
    - *Normal block end* — unchanged semantics, new mechanism (flush to the block's watermark).
    - *Explicit `return expr`* — emits `({ __auto_type _ret = (expr); <defers LIFO>; return _ret; })`, so the return value is materialised **before** cleanup runs — a defer that releases a resource cannot invalidate the value mid-construction.  Value-less `return` just runs defers.
    - *`?` error propagation* — the Err branch of the statement-expression now flushes pending defers after `_t` is materialised, before `return _t`.
C : Defer tracking moved from per-block re-scan (`cg_emit_defers` walked the statement list backwards at block end) to a per-function stack in `CG` (`defers[64]`, `n_defers`).  Blocks record a watermark on entry, push ST_DEFER statements in order, flush LIFO to the watermark at exit, and pop.  `EX_RETURN` / `EX_TRY` flush the whole stack (floor 0) because they exit the function, not the block.
A : `URUS_CG_MAX_DEFERS = 64` — pending-defer cap per function; exceeding it is a codegen diagnostic, not a silent drop.
A : `tests/run/22_defer_early_return.urus` — cleanup fires on early-return and normal paths.
A : `tests/run/23_defer_question.urus` — cleanup fires on `?`'s Err propagation and on the Ok path.
U : `06-LANGUAGE-GUIDE.md` defer section rewritten: exit-edge list, value-before-defers ordering, 64-cap, "defers must not return".  The *What is missing* entry is deleted.
N : Defers containing `return` are not yet rejected by sema — grammar makes it unlikely; the explicit check is v0.0.2.
