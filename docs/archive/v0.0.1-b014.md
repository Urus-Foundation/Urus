## Changes

S : `F-MEM-1` *fixed* — **the URUS-to-C code-injection primitive is closed.**  Previously, `cg_fmt_arg_array` copied whatever bytes sat between `{` and `}` inside an f-string straight into emitted C as the operand of `URUS_FMT_ANY(...)`.  Source like `f"x={system(\"…\")}"` produced `URUS_FMT_ANY(system("…"))` and the host C compiler obediently linked the call.  This was a Critical RCE primitive against anyone compiling untrusted `.urus` source.  v0.0.1-b014 adds `validate_fmt_placeholder`: each `{…}` must be a `.`-separated sequence of identifiers (`[_A-Za-z][_A-Za-z0-9]*`), bounded by `URUS_FMT_MAX_PLACEHOLDER = 256` bytes, with no empty placeholders, no leading / trailing / consecutive dots, no NUL bytes, and no other characters.  Rejected placeholders emit a precise URUS-level diagnostic and **do not** splice their bytes into the C output.  Unterminated `{…` (missing closing brace) is also rejected.
A : `URUS_FMT_MAX_PLACEHOLDER = 256` — upper bound on placeholder length.
A : `is_ident_start` / `is_ident_cont` / `validate_fmt_placeholder` helpers in `compiler/src/codegen_c.c`.
A : `tests/fail/SEC-08_fstr_calls.urus` — call-syntax placeholder (`{evil()}`) rejected.
A : `tests/fail/SEC-09_fstr_empty.urus` — empty `{}` rejected.
A : `tests/fail/SEC-10_fstr_dot_only.urus` — malformed dot chain (`{.n}`) rejected.
A : `tests/run/13_fstr_dotted.urus` — well-formed `name`, `obj.field`, `a.b.c` paths still compile.
U : `tests/fail/SEC-01_fstr_injection.urus` — original RCE PoC now triggers `invalid character '(' in f-string placeholder` and stops the build.
I : `cg_fmt_arg_array` signature gained `SrcLoc loc` so diagnostics carry source position.  Both call sites — `try_emit_println_call` and the standalone `EX_FSTR_LIT` branch — pass `a0->loc` / `e->loc` respectively.
I : The splicing path was rewritten to copy validated bytes one at a time via `sb_putc` (previously a printf-formatted heap allocation), which keeps the emit hot-path malloc-free for legal cases too.
N : 9 of 10 stop-ship findings now closed.  Remaining: **F-TY-2** (Result/Option int64-truncated payload) — the most invasive of the original audit set, requires monomorphisation and a payload-storage redesign.
